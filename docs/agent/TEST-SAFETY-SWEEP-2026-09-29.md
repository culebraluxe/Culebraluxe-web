### WBS 2 — the premise is not in this repository (measured, closed)

`coexist` occurs three times in the Rust tree and none of them is behaviour:

- `rust/ui/src/app/registry.rs:176` — a route key, `"whatsapp-coexistence"`, registered as `Kind::External`;

### WBS 6 — the parity ledger can no longer be regenerated (measured)

  hand-edit. The run FAILS if the map and the repository disagree."

## What the sweep found that nobody had recorded

### A. Every guardrail path in `AGENTS.md` is dead — the "Never" list has no enforcement

`AGENTS.md` names a guard test for seven of its nine "Never" rules (lines 133, 151, 160, 161, 162, 164, 166, 172).
None of the paths exists, and none survives under `legacy/` either — `legacy/workflow_app/tests/` contains only
`fixtures/`. The missing files are `workflow_app/tests/{publish-scan-coverage,no-tree-residue,forge-qa-no-git,
worker-commit-identity,db-routing,whatsapp-attribution,column-writer-audit}.test.ts`.

The same lint knows how to check a path for a map (`docs/agent/MAP-engine.md`, `docs/agent/ORIENTATION.md`) and a
manifest (`docs/agent/manifest/*.md`) — it reports those as warnings — but it has no rule for a `guard:` path in
the handbook, which is the one place a dead pointer means a rule is silently unenforced.

The machinery that could catch this already exists and stops one step short:
`rust/cli/src/forge/vendor_block.rs:168` (`orphaned_guardrails`) checks that a guardrail's anchoring **sentence** is
still present in the handbook, but nothing anywhere checks that the guard **path** it names exists. A guard that
cannot run is not a guard; the check belongs beside the one that already runs, and it is the cheapest fix in this
document.

### B. `AGENTS.md` still calls nine deleted TypeScript files canonical

Measured, all missing: `lib/server-error-capture.ts`, `lib/error-capture-seam.ts`, `lib/service-error-sink.ts`,
`db/app-error.ts`, `scripts/probe-error-capture.ts`, `scripts/pull-prod-to-dev.mjs`, `scripts/forge-packet-lint.ts`,
`agent-runtime/repo-context.ts`, `services/core/base-service.ts`. The Error Capture Obligation (`AGENTS.md:389`)
and the "Two rules, both mechanical" block are written as instructions for a tree that no longer exists — an agent
following them is told to reuse seams that are gone. The Rust equivalents are real and are the ones to name.

### C. A story left at `Ready` can never be dispatched again (mechanism confirmed in code)

`db/migrations/025_agent_work_queue.sql:104` fires the dispatch trigger only when
`new.status = 'Ready' and (tg_op = 'INSERT' or old.status is distinct from 'Ready')`. An already-`Ready` row that
loses its work item is therefore invisible forever: no trigger, no item, and the worker's claim query
(`rust/core/db/src/forge_control.rs:264-274`) only ever looks at `agent_work_item`. Two stories seeded `Ready` in
`db/loads/stories_2026_09_28.sql:10` and `:26` show the symptom — `open work items: 0` while both sit at `Ready`
— and this morning's `forge:clean --force` cancelled open work items on PROD, which is exactly how a `Ready` story
becomes an orphan. The mechanism is certain; whether those two rows are orphans for this reason has not been
confirmed against the rows, because no read-only SQL verb exists in `cli`. Any fix must make the trigger fire for a
`Ready` row without an active item, not merely on the transition.

### D. A path hypothesis was refuted, and not acted on

`opencode` is not missing from the worker's environment: under a launchd-shaped environment
(`env -i HOME=… PATH=/opt/homebrew/bin:…`) it resolves at `/opt/homebrew/bin/opencode`. No fix was made, because
there was nothing to fix. Recorded so the next lane does not "repair" it again.

## Closed after this sweep

The two findings this document raised about `AGENTS.md` are enforced now, not noted. Both landed under
`ENG-GUARD-AGENTS-LINT-01`.

- **A — every guard path is linted.** `rust/cli/src/forge/guard_paths.rs` reads every `guard:` clause in
  `AGENTS.md` and fails when the path does not exist, when it exists but holds no test (an empty file is not a
  guard), when a `Never` rule declares no guard at all, or when a bare `guard: NONE` gives no reason. It is
  blocking as `forge guard-lint` (`.github/workflows/gates.yml`, static job), it runs inside `forge harness-lint`,
  and the unit test `the_real_handbook_guard_paths_resolve_to_tests_on_disk` runs it against the committed
  handbook under `cargo test --workspace`. The eight dead `workflow_app/tests/*.test.ts` lines now point at the
  Rust tests that hold each rule.
- **B — no deleted TypeScript path is called canonical.** The Error Capture Obligation seam list, the "Two
  rules, both mechanical" block and the DEV_OPS playbook reference all name the Rust modules that exist; the
  nine dead TypeScript paths (`lib/*`, `db/app-error.ts`, `scripts/*`, `agent-runtime/*`, `services/core/*`) are
  gone from the handbook.

Verified on the corrected handbook: `forge guard-lint` → PASS (0 findings); the deliberately-broken copy
returns exit 1 with `guard-path-missing` / `guard-path-not-a-test` / `guard-none-without-reason`, each naming
its line and path.
