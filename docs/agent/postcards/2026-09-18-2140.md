## Four defects found, every one of which had been reporting health

1. **A cleaner that could not clean.** `pnpm health` judged branches by **ancestry** while work lands by
   rebase and cherry-pick: `--merged` said "not merged" about 106 branches while `git cherry` said their
   patches were all applied. 168 branches had accumulated, and `git branch -d` refuses those same branches
   for the same reason. Now judged by patch; only tooling-owned branches are deleted. **Refs 1,347 → 19;
   local branches 112 → 4.**
2. **A fence that proved a setup the engine did not have.** The worker commit path stamped no git
   identity, so on a machine without git config it used git's placeholder: **228 commits authored
   `Your Name <you@example.com>`**. The fence never caught it because the fence configured
   `user.email = eng21@test` itself — it asserted the commit's contents and never its author. Fixed by
   stamping `GIT_AUTHOR_*`/`GIT_COMMITTER_*`; the new fence builds a repo **whose config IS the bug**.
3. **The generator gap is still open.** Lanes and dogfood rehearsals still leave their branch behind; the
   counter-wipe removes it now. Not fixed at the source — that needs its own story, and I refused to
   smuggle it into a sprint that was closing.
4. **`CI-PRODUCTION-FENCE-01` was reversed by the captain**, and it was mine. I added a token-gated
   deploy job so a red main could not reach production. Inert (no token secret), but its skip message
   told the next reader how to activate it — the repository was carrying written instructions to restart
   a cost. He measured the cost: CI deploys were **doubling the bill**, 30 builds a day where 1–2 were
   wanted. Job deleted; the file now says DO NOT ADD ONE. The honest residue: CI reports a red main and
   the operator decides. If that guarantee is wanted back it belongs in `pnpm release` as a **refusal**
