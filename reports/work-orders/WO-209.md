## Motivation (from WO-203)

`reports/work-orders/WO-203.md:34` pinned the requirement: preflight must assert the `session list` shape contains `agentSessionId` (the key WO-204's liveness check depends on), not just `--version`. The probe behind it (`reports/fixtures/WO-203-send-session-probe.json`):

- `send --session` is the only resume path and validates against `/^ses/` (probe 3); it performs **no existence check** (probe 4), so the `maestro_session_lists` membership test is the ONLY guard against resuming a stale id.
- `session list --json` entries carry both `"sessionId"` (tab UUID) and `"agentSessionId"` (`ses_*`), and only the latter satisfies the resume validator (probe 5).

Pre-WO-209, `verify_vendor_contract` proved only that the binary spawns and answers `--version` — a CLI that drifted either resume shape would pass preflight and then silently open fresh every turn (wrong liveness key) or build turns against flags the CLI no longer accepts (moved `--session`).

## Red (failing tests first)

New tests in `forge/src/engine/maestro.rs:1984-2089` assert the contract against drifted fixtures derived from the WO-203 capture:

- `maestro_preflight_fails_on_drifted_send_help` (`:1990`): `send --help` without `--session` is drift; error must name `--session`.
- `maestro_preflight_fails_on_session_list_without_agent_session_id` (`:2002`): `session list --json` entry without the `agentSessionId` key is drift; error must name `agentSessionId`.
- `maestro_preflight_drifted_fixture_fails_vendor_contract` (`:2033`): end-to-end through `verify_vendor_contract` against a fake CLI that answers `--version` yet serves both drifted shapes — must fail. **A `--version` answer alone never passes.**

Against the old code (version-only check) all three fail: `check_send_help_shape` / `check_session_list_shape` do not exist (`E0425`), and the drifted fixtures pass preflight.

## Fix

In `forge/src/engine/maestro.rs` (all under Owns):

- `verify_vendor_contract` (`:1098`): after the `--version` answer, runs `verify_send_contract` (`:1126`) and `verify_session_list_shape` (`:1173`); the `Ok` line now carries all three (`{version} @ {bin} (send --session ok; sessions={n})`).
- `check_send_help_shape` (`:1154`): asserts the `send --help` text (captured contract: maestro-cli 1.0.0, 2026-10-12) documents `--session` (the exact resume flag WO-204 depends on: `-s, --session <id>`) and describes `send`. Missing flag is drift; the ERROR names it.
- `check_session_list_shape` (`:1205`): parses `session list --json`, requires the `sessions` array, requires every entry to CARRY the `agentSessionId` key. A null value passes (see correction below); a non-string value or a missing key is drift; the ERROR names the entry index and the key.
- `maestro_preflight_pass_and_fail` (`:1472`): updated from the `/usr/bin/true` stub to a fake CLI serving the captured help/list shapes (full contract now, not just `--version`); `/usr/bin/false` and missing binary still refuse.
- Companion passing tests: `maestro_preflight_passes_captured_send_help` (`:1997`), `maestro_preflight_passes_captured_session_list` (`:2009`, asserts count 2), `maestro_preflight_passes_session_list_with_null_agent_session_id` (`:2016`, null key + empty array), `maestro_preflight_captured_fixture_passes_vendor_contract` (`:2065`), plus ignored live-CLI read-only check `maestro_preflight_live_cli_passes` (`:1969`, requires maestro-cli on PATH; runs no turn, opens no tab).

No changes to the turn path: `build_maestro_send_args` (`:751`, passes stored id to `--session`) and `maestro_session_lists` (`:764`) are untouched consumers of the now-guarded shapes.

## Correction found by the live CLI (not in the plan)

The first cut required every entry's `agentSessionId` to be a non-empty string. The live `session list --json` (53 sessions, 2026-10-12) disproved it: 5 fresh tabs carry the key with a **null** value (no agent session yet — e.g. unnamed `ChatGPT`, `Numetron2`, `LongCat`, `Step5`, `wo/204` tabs), and the ignored live test failed on entry 5. The check now asserts key PRESENCE; null entries pass because they can never match a stored id, so the liveness check stays safe. The drift fixture (key absent entirely) still fails. `maestro_preflight_passes_session_list_with_null_agent_session_id` pins both the null case and the empty-array case.
