# WO-109: Fix the vacuous contract test

## Summary
Rewrote the test `api_route_contract__007__service_error_mapping.rs` to reference real production symbols from `web/src/api/error.rs` instead of a local mock `ServiceError` enum. Proved the test is no longer vacuous by deliberately breaking the error mapping in production code and watching the test fail, then restored the mapping.

## Changes
1. **tests/tests/api_route_contract__007__service_error_mapping.rs**: Completely rewrote to test real `ApiError::from` conversions for:
   - `CoreServiceError::Business` with various codes (NOT_FOUND, CONFLICT, validation)
   - `CoreServiceError::Runtime` variants (Forbidden, Router, Authorization, Audit, Event)
   - `ServiceDispatchError` variants (ServiceNotFound, UnknownOperation, InvalidPayload, Operation with different classes, ServiceDraining, ServiceStopped, OperationPanicked)
   - Correlation ID support via `with_correlation`

2. **tests/Cargo.toml**: Added `http-body` and `http-body-util` dependencies for response body collection.

3. **Proof of non-vacuous**: Deliberately changed `StatusCode::NOT_FOUND` to `StatusCode::BAD_REQUEST` in `web/src/api/error.rs` for the `_NOT_FOUND` code mapping. The test failed with "Expected status 404, got 400". Restored the correct mapping and test passes.

## Verification
- Test passes (`cargo test -p test-harness --test api_route_contract__007__service_error_mapping`)
- Forge tests pass (`cargo test -p forge --lib` - 384 passed)
- Clippy clean - no new warnings from changes
- Test fails when production error mapping is deliberately broken
