## Work

1. **Post-hoc verdict in `maestro.rs` (`run_role`, after `parse_maestro_output`).** `maestro-cli send` returns ONE JSON object after completion (keys `agentId agentName sessionId response success error usage` — WO-203 probe), so a mid-turn kill from vendor numbers is best-effort only; the verdict that always holds is post-hoc. The streaming kill now reads the real camelCase keys (`inputTokens`/`totalCostUsd`) with tolerated snake_case aliases, and carries the same `BUDGET_EXHAUSTED` line as the verdict.
2. **All three spend-cap functions live in `forge/src/engine/spend_cap.rs`.**
   - `forge_spend_should_hold(Option<f64>, Option<f64>) -> bool` — holds only on a measured figure over the cap; `None` on either side holds nothing.
   - `render_spend_cap_line(Option<f64>, f64) -> String` — `BUDGET_EXHAUSTED: {spend:.6} USD measured against a {cap:.6} USD cap (FORGE_SPEND_CAP_USD)`; unmeasured spend renders as words, never a fabricated `$0.000000`.
   - `check_post_hoc_spend_cap(Option<&HarnessUsage>, Option<f64>) -> Result<()>` — takes the usage ref, reads `usage.cost_usd` through `forge_spend_should_hold`, fails with the `BUDGET_EXHAUSTED` line. `maestro.rs` imports it instead of defining its own (private copy removed).
3. **Enforcement shape:** missing usage is UNKNOWN spend, never $0 (WO-203 residual risk: `usage: null` never trips the cap); no configured cap holds nothing. The wall-clock ceiling stays the live stop.
