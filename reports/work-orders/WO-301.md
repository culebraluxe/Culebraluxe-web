# WO-301 Report

## Summary
Fixed the durability bug where a transient final-heartbeat failure after a paid turn execution could cause the same turn to be re-executed. Also made poison-sensitive lock sites in the heartbeat supervisor poison-tolerant.

## Pre-fix SHA
`6852fc081606c49d830bbc0afc8f22be86348e64`

## Changes Made

### 1. Final-heartbeat failure path in `forge/src/engine/executor/drive.rs`

**Symbols corrected:**
- `drive_forge_story_inner` (non-parallel path, lines ~1169)
- `drive_forge_story_inner` (parallel path, lines ~1202)

**Old behavior:** `durable.jobs.complete(&lease.job_id, opts.worker_id)?` propagated the error with `?`, causing the drive to return an error. On the next pass, the Workflow task would still be READY (since the completion write failed), causing the turn to be re-executed and paid for again.

**New behavior:** When `durable.jobs.complete` fails:
- Log the error with a "preserving paid turn for reconciliation" message
- Continue without propagating the error
- The Workflow task remains in a state requiring reconciliation
- A later Forge pass will reconcile the durable state without re-executing the turn

**Handling chosen:** Record and continue (WO-301 pattern B/C) — the paid turn fact is preserved, persistence failure is recorded, reconciliation is enabled.

### 2. Poison-tolerant locks in `forge/src/engine/job.rs`

**Symbols corrected:**
- `heartbeat_state.consecutive_db_failures.lock()` at two sites in the heartbeat supervisor (lines 434, 438)

**Old behavior:** `.lock().unwrap()` would panic if the mutex was poisoned, crashing the heartbeat supervisor and losing lease authority.

**New behavior:** `.lock().unwrap_or_else(|poisoned| poisoned.into_inner())` recovers the inner value from a poisoned mutex, allowing the heartbeat supervisor to continue operating.

**Handling chosen:** Propagate with recovery — poison is handled locally without panicking the durability path.

### 3. WO-121 prerequisite fixes in `forge/src/engine/executor/drive.rs`

**Symbols corrected (error-loss sites):**
- `discard_unstarted_lane_worktree` calls (4 sites in `prepare_durable_batch`)
- `jobs.fail` calls (2 sites in `execute_durable_batch`)
- `remove_lane_worktree` call (1 site in TASK_ALREADY_COMPLETED handling)
- `durable.jobs.fail` call (1 site in integration failure handling)
- Environment variable parsing (4 sites using `.ok()`)

**Old behavior:** Silent error discarding with `let _ =` or `.ok()`

**New behavior:** Errors are logged via `eprintln!` but propagation continues correctly

**Handling chosen:** Record and continue for cleanup errors; proper filtering for env vars.

## Residual Risk

1. **Worktree cleanup on panic**: The `execute_durable_batch` uses `catch_unwind` and returns results for all lanes including panicked ones. The main loop cleans up worktrees for successful completions (line 948-955) but retains worktrees for engine faults (line 805-809 logs "isolated worktree retained"). This is intentional for debugging but could leave orphaned worktrees on repeated engine faults.

2. **Reconciliation automation**: The fix preserves the paid turn for reconciliation, but the actual reconciliation pass (a later Forge run) must be triggered manually or by the scheduler. No automated reconciliation trigger was added.

3. **TASK_ALREADY_COMPLETED handling**: In the non-parallel path, when `TASK_ALREADY_COMPLETED` is returned, we now log and continue instead of propagating. This is correct because the Workflow task is already complete, but the durable job needs settlement. The settlement failure is logged for reconciliation.
