## Part A — Hold authority

- Aggregation symbol: the wave loop over `executions` in `drive_forge_story_inner` (sibling fold at former
  `if let Some(error) = engine_fault { return Err(error); }` ahead of the `hold_reason` arm).
- Old precedence: any lane engine fault returned `Err` before the Hold arm was read, so `Lane A → Hold` +
  `Lane B → engine fault` disposed as engine error and the genuine Hold never became a Hold.
- New behavior: `classify_lane_failure` splits each failed lane into verdict channels (business Hold vs
  engine fault, error object never cloned); `wave_disposition` returns Hold whenever any lane holds, with
  the sibling fault eprintln-logged and attached to the Hold reason; the fault propagates untouched only
  when no lane holds, and never invents one.
- Chaos test A: `a_real_hold_survives_a_sibling_engine_fault` (two real lanes via `execute_durable_batch`,
  folded exactly as the loop folds) plus `an_engine_fault_alone_propagates_without_inventing_a_hold` and
  `a_hold_alone_carries_no_fault_attachment`.
- Red-before: with the precedence flipped to fault-first, test A fails with
  `the engine fault masked the genuine Hold: db: DatabaseUnavailable during workflow.step`.
- Green-after: all three pass; Hold reason carries both the verdict and the fault text.

## Part B — settle durability

- Completion symbol: the wave-loop settle `durable.jobs.complete(..)` after a completed lane (normal and
  `TASK_ALREADY_COMPLETED` arms); the direct-path equivalents already logged and continued.
- Previous behavior: settle failure set a bare Hold reason with no diagnostic line and no reconciliation
  vocabulary.
- New behavior: `settle_completed_lane` — `match` with log-and-continue and reconciliation: eprintln diagnostic,
  Hold reason naming the task plus "preserving paid turn for reconciliation", the job row untouched (never
  failed, never completed by the helper), outcome preserved, loop continues through normal result construction.
- Chaos test B: `a_settle_blip_holds_with_reconciliation_instead_of_orphaning_the_job` (fake `JobService`
  whose `complete` fails transiently; `fail` panics if called) plus `a_clean_settle_holds_nothing`.
- Red-before: with the helper reduced to swallow (`Err(_) => None`), test B fails (no Hold reason).
- Green-after: both pass; `complete` attempted once, `fail` never called.
