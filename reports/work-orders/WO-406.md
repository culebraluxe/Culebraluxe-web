## The file-reading guards, again

Three structural guards read these files as text, and WO-404's lesson applies: a guard that reads a path that no longer
exists fails the build (the good case), and a guard pointed at a stale path would pass while covering nothing (the bad
one). All three take the production half via `source.split("#[cfg(test)]").next()`, so pointing them at each module's
`mod.rs` keeps exactly the coverage they had:

- `roles/service.rs` — `no_concrete_service_copies_the_lifecycle` reads each lane's file; `include_str!("smith.rs")`
  became `include_str!("smith/mod.rs")` and `include_str!("qa.rs")` became `include_str!("qa/mod.rs")`. The other five
  lanes are still single files and are untouched.
- `roles/lifecycle/tests.rs` — `the_shared_lifecycle_names_no_lane` reads its own module's source;
  `include_str!("lifecycle.rs")` became `include_str!("../mod.rs")`.
- `engine/job` and `engine/opencode` reference no `include_str!` of their own sources; the only other reader of these
  paths was `cargo check`, which is how the two above were found.

## The commit ordering, and why the history is not as tidy as the work

`git mv` stages the rename the moment it runs, so by the time the first of these five commits was written all five
module directories had already been staged. Staging one file group at a time then only re-staged content: every rename
went in with the first commit, and each later commit added its own split and its own guard fix-up. The four commits
below the tip therefore have a guard reading a file that commit no longer has:

| commit | `include_str!` targets that do not resolve there |
| --- | --- |
| `f685cdae1` job | `roles/smith.rs`, `roles/qa.rs`, `roles/lifecycle/lifecycle.rs` |
| `6339ced8b` opencode | the same three |
| `e53818e15` smith | `roles/qa.rs`, `roles/lifecycle/lifecycle.rs` |
| `4bc5dccbb` qa | `roles/lifecycle/lifecycle.rs` |
| `c8344b4e2` lifecycle (the tip) | none; 22 of 22 resolve |

A re-cut of the same five commits, each one green and carrying the same tip tree, was built and checked locally. `main`
refused it: `remote: error: GH006: Protected branch update failed ... Cannot force-push to this branch`. So the history
stays as it is, and this table exists so that nobody has to find it by checking out `f685cdae1`. The tip is what CI
compiles and what branches grow from, and the tip is green: it carries the whole split and every guard fix-up. For the
next split of this kind: stage each rename and its new content together, one `git add` per file, instead of letting
`git mv` stage all of them up front.
