# WO-403 Report

## Summary

`main` in `forge/src/bin/forge.rs` was a single 694-line function that read the launch configuration, answered three
subcommands and drove a story. The launch is now a parsed `Cli` struct, `main` is 18 lines, the subcommands and the
drive are their own functions, and eight contract tests state the flags, their environment fallbacks, the refusals
and the exit codes. No behaviour changed: the CLI contract was captured from the old binary and the new one and the
two are identical, byte for byte, across seven invocations.

## Pre-fix SHA

`e716149ca7083286e2a73a9a3b6393a021f63806` — the WO-407 commit, the head this work started from.

## Changes Made

### 1. `Cli` — the launch, parsed once

`story`, `work_type`, `work_item`, `claim_fence`, `stop_after`. Each field takes the flag first and the environment
variable it mirrors as the fallback, which is the precedence the scattered `flag()`/`env::var()` pairs already had.
What the LAUNCH said lives in the struct; what the MACHINE says (the worktree, the base ref, the store, the
budgets) stayed in the environment and is still read where it is used.

### 2. `CliRefusal` — a refusal as a value

The parse used to print and `exit(2)` from five places inside `main`, so "the flags were read" and "the process
ends" were the same statement. A refusal now carries its message and its status; `main` prints the message and exits
with the code. The refusal ORDER is unchanged — `reject_configuration` still runs before the message is printed, so
a refused claim is still settled before the refusal is reported.

### 3. `subcommand`

`learn --dry-run` (exit 0, or 1 when the learn pass or the current directory fails), `profile-compare` (exit 0, or 1
when the report cannot be read) and `harness-info` (exit 0, or 2 when the vendor cannot be resolved) are answered
before a launch is parsed, in `subcommand`, `learn_dry_run`, `print_harness_info` and `harness_identity_line`. The
`harness=` lines are assembled from the same calls as before.

### 4. `run(cli, budget)` — the drive, moved verbatim

The 549 lines that were the body of `main` are now the body of `run`, unchanged: old lines 293-841 and new lines
410-958 are byte-identical (`diff` clean), and `git diff` aligns the block as context, so the whole change counts 435
insertions and 137 deletions in one file — the deletions being the old `main`'s head, the three subcommand blocks and
the parse block.

The budget install stayed in `main`, before the parse, on purpose: a refused launch settles the claim it was refused
for, and that write must run under the engine's database budgets like every other one.

### 5. `claim_fence_from_args` takes the environment reader

Same signature treatment as `Cli::from_args_with`: the reader is a parameter, so the contract test can state both
halves of the precedence without mutating the process environment that every other test in this binary shares.
`ALLOWED_WORK_TYPES` replaces the `const ALLOWED` that was declared inside `main`.

## The CLI contract, captured from both binaries

Not asserted from the source: the HEAD binary and this one were both built, and seven invocations were run against
each — no arguments, an unknown `--work-type`, a lowercase `--work-type`, a `--work-item` with no owner, an
unreadable `--stop-after`, and two unreadable `--claim-generation` values (a word, and a number too large for
`i64`). stdout, stderr and the exit status are identical for all seven; every refusal is exit 2. The eight new
`cli_contract_tests` state those same rules against `Cli::from_args_with`, including the two the wave's own rules
turn on: a claim with no authority is not fenced (`FORGE-B1` §10.4), and a cap or a work type that cannot be read is
refused rather than widened.
