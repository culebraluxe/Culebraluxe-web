# WO-404 Report

## Summary

`forge/src/engine/maestro.rs` (2188 lines) is now a module directory whose largest file is 543 lines. The seam is the
one the file already drew for itself: the roster and the session marker, the harness and its three trait impls, agent
resolution, the streaming runner, and the vendor preflight. `output.rs` was already a submodule and did not move.

The 2188 line file was 1140 lines of behaviour and 1048 lines of tests, so the tests had to move too: they are now
`tests/{args,harness,output,session,stream}.rs`, each `use super::*`, each holding the blocks that exercise its subject.
The three shared helpers (`lock_env`, `write_fixture_script`, `run_fixture_with_outer_deadline`) stay in
`tests/mod.rs` where every child can reach them.

## The two structural guards, which is the part worth reading

Two tests read the module as text: `maestro_agent_selection_ignores_forge_role_ids` locates the resolver's signature and
refuses a role or node parameter, and `maestro_target_selection_never_calls_opencode_resolver` scans the code (with `//`
comments stripped) for OpenCode resolution symbols. Both used `include_str!("maestro.rs")`, which after this change
would have read `mod.rs` — 78 lines of re-exports, containing neither the resolver nor the runner. Both guards would
have passed while covering almost nothing.

They now call `maestro::tests::maestro_module_source()`, which concatenates all seven production files, so the scanned
text is the union of the module rather than one file of it. That is a deliberate widening of the input, not a
behaviour change: the guard asserts the same absence over strictly more code.

## Visibility

`maestro/output.rs` already used `pub(super)` for the items the parent reaches; the moved items follow it. Fifteen
declarations - eight in `session.rs`, two in `args.rs`, four in `stream.rs`, one in `preflight.rs` - became
`pub(super)`, and `MaestroHarness::task_text` did too, because a session test calls it. Nothing became `pub`: the
crate-facing surface (`MaestroHarness`, `agent_alias`, `resolve_maestro_agent`, `verify_vendor_contract`, the
`MAESTRO_*` constants, the `VENDOR_SESSION_LANE`/`SESSION_MARKER_FILENAME` pair) is re-exported from `mod.rs` at its
old path, so no caller outside the module moved.
