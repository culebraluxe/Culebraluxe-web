- **Verdict: `send --session` expects the `agentSessionId` (`ses_*`) value, NOT the `sessionId` (tab-UUID) value.**

## Probe (real CLI v1.0.0, 2026-10-12, target: Meta Muse `f35347b5-8d8d-46f6-a50e-79a776dee013`, `--read-only`)

1. Fresh `send` (no `--session`) mints the session and returns it in the envelope's **`sessionId`** key — whose value is `ses_*`-shaped:
```json
{"agentId": "f35347b5-8d8d-46f6-a50e-79a776dee013", "agentName": "Meta Muse", "sessionId": "ses_ecf684e0dffehGfsQ9wkmL4Yep", "response": "probe-ok", "success": true, "usage": null}
```
2. Resume with `--session ses_ecf684e0dffehGfsQ9wkmL4Yep` **continued the conversation** (it remembered `probe-ok`) and echoed the same id — the `ses_*` value is a valid `--session` id.
3. Resume with a tab-UUID-shaped id (`--session 00000000-0000-4000-8000-000000000000`) is **rejected**:
```json
{"agentId": "f35347b5-8d8d-46f6-a50e-79a776dee013", "agentName": "Meta Muse", "sessionId": null, "response": null, "success": false, "error": "Expected a string starting with \"ses\"\n  at [\"sessionID\"]", "usage": null}
```
stderr: `maestro-cli send failed: Expected a string starting with "ses"`. The CLI validates `--session` against `/^ses/` and names the wire field `sessionID`.
4. Resume with a well-formed but nonexistent id (`--session ses_00000000000000000000000000`) returns `success:true` with the id echoed — **`--session` performs no existence check**; a stale id fails silently into that id.
5. `session list --json` entries carry **both** keys: `"sessionId": "<tab-UUID>"` (== `tabId`) and `"agentSessionId": "ses_*"` (opencode; other tool types use UUIDs there). Only the `agentSessionId` value satisfies probe 3's validator.

Full captured output: `reports/fixtures/WO-203-send-session-probe.json` (probes 1–5 verbatim, plus envelope notes for WO-205).

## Consequences for the lane (re-pinned at this base)

- `forge/src/engine/maestro.rs:751-758` (`build_maestro_send_args`): passing the stored id to `--session` is **correct as-is** — the stored id comes from the envelope's `sessionId`, which probe 1 shows is already the `ses_*` value.
- `forge/src/engine/maestro.rs:764-796` (`maestro_session_lists`): line 785 matches the stored id against entry **`sessionId`** — **wrong key**. A stored `ses_*` id can never equal a tab UUID, so the liveness check always returns false and every turn opens fresh. WO-204 must compare against entry **`agentSessionId`** (scoped to the same agent, as the current `agentId`/`agentName` conjunct already does). Load-bearing because of probe 4: this membership test is the ONLY guard against resuming a stale session.
- Envelope parse (`maestro.rs:1037-1039`, primary key `sessionId`): **correct** — no change needed in WO-205's parsing of the session key.
- For WO-205: the envelope is a **single JSON object, not a stream** (keys `agentId agentName sessionId response success error usage`); under `--read-only`, `usage` is `null`, so the real `inputTokens`/`totalCostUsd` keys must be observed on a non-read-only turn.
- For WO-209: preflight must assert the `session list` shape contains `agentSessionId` (the key WO-204 will depend on), not just `--version`.
