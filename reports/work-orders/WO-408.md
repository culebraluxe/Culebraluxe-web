# WO-408 Report

## Summary

The twenty-two `eprintln!` sites in the five modules WO-406 built now emit `tracing` events, `forge` installs a
`tracing-subscriber`, and the four binaries that can emit them install it at the top of `main`. Before this commit the
engine's turn, job and interrupt lines were formatted strings written straight to stderr: nothing could filter them and
no field could be selected. The larger half of the problem was the other direction — the crate already depended on
`tracing` and `pianola/*` already emitted eleven `info!`/`warn!` events that no process in this repo installed a
subscriber for, so those eleven were being dropped in silence. A dropped event is worse than a print: a print cannot be
turned off by accident.

The twenty-two lines are now the same lines structurally — same fields, same values, same order of decision — with a
level that says which of them are news (a lease was lost, a renewal failed, a stream line did not parse) and which are
the record of a normal turn (spend, agent declaration, delivery receipts).

## Before and after

`eprintln!("spend story={story_id} node={node_id} run={} tokens_in={} …")`, for example, becomes:

```rust
tracing::info!(
    story = %story_id,
    node = %node_id,
    run = %ctx.story_run_id.unwrap_or("(none)"),
    tokens_in = usage.tokens_input,
    tokens_out = usage.tokens_output,
    cost_usd = %format!("{:.6}", usage.cost_usd),
    session = %usage.session_id,
    "spend"
);
```

Three rules were applied at every site:

1. **The discriminating token stays in the message.** `forge-interrupt requested=true`, `delivered=pending`,
   `delivered=true`, `usage=unknown`, `harness=opencode` keep those words as the event's message rather than as a
   field, so a `grep` for a line's verdict still works.
2. **Everything that varies becomes a field**, with `%` for `Display` and `?` where the old format was `{:?}`
   (`signalled`, `exit_code`) — `signalled=Some(SIGTERM)` is now selectable instead of only printable. `cost_usd` keeps
   its six decimals (`%format!("{:.6}", …)`) because that column is read by eye and compared between turns.
3. **Level by consequence, not by verbosity.** The eleven failures are `warn!`: six in `job` (delivery error, settle
   failure, heartbeat, two lease losses, final renewal), four in `opencode` (stream parse failure, interrupt observed,
   both session writes) and one in `lifecycle` (the observer write). The eleven turn records and receipts are `info!`.
   Under the default filter both are visible; under `RUST_LOG=warn` the noise of a healthy run goes away and the
   failures do not.

One site needed a local rather than a chain: the turn summary's `stopped_by` was a four-line `result.stop.…` expression
inside the old argument list, and it is now a named `stopped_by` bound before the event.

## Changes Made

### 1. `forge/src/observability.rs` — the subscriber

New module, mirroring `web/src/observability.rs` (the HTTP process's half of the same decision): an `EnvFilter` from
`RUST_LOG` defaulting to `info`, the `RUST_LOG_FORMAT=json` switch, and `try_init` rather than `init` so a second
installer in the same process — the worker and the HTTP process can share one — is a no-op instead of a panic.

One deliberate difference from `web`: the writer is **stderr**, not stdout. These lines were `eprintln!` before and a
script that starts a run reads them there, and the `forge` CLI's machine-readable output already owns stdout; leaving
the layer on its default stream would have put log lines into a consumer's parse. The fallback path (`try_init`
returning `Err`) is an `eprintln!` on purpose: a subscriber that could not install has no subscriber to report through.

### 2. `forge/Cargo.toml` — one dependency

`tracing-subscriber.workspace = true`, beside the existing `tracing.workspace = true`. The workspace dependency already
carries the features this needs (`env-filter`, `fmt`, `json`); nothing was added to the workspace manifest.
`Cargo.lock` moves by one line — the package already existed (`web` depends on it), so only the `forge` dependency edge
is new.

### 3. The four binaries

| binary | why it installs the subscriber |
| --- | --- |
| `forge` (`forge.rs`) | the engine child: this is the process the twenty-two events are actually emitted in |
| `forge-worker` (`forge_worker.rs`) | the resident worker and parent of the child above; its share of the events is emitted in-process |
| `forge-task` (`forge_task.rs`) | drives the engine API in-process (dev tool) |
| `re-workflow` (`re_workflow.rs`) | drives residential workflow jobs in-process |

`init()` is the first statement of `main` in all four, before argument parsing: a launch refused for a bad flag still
reports through the engine's events, and an event emitted before the subscriber exists is an event that vanishes.
`forge-assay-plan-hash` is deliberately not wired: it hashes files and emits nothing.

### 4. Two rustfmt side effects in files this work order already edits

`cargo fmt -p forge` was run as part of the verification of a tree that was not rustfmt-canonical (the in-flight edits
below), and two spots in files this work order edits were formatted on the way past: `roles/lifecycle/mod.rs`'s
`use crate::engine::runner::{ForgeRoleOutcome, ForgeRoleRunner};` moved from line 27 to line 34 (into sorted position
among its group — the import itself is unchanged) and a doubled blank line before `#[cfg(test)] mod tests;` in
`engine/opencode/mod.rs` collapsed. Neither touches a statement; both are in this commit because a file goes in whole.

## Verification

- `cargo fmt -p forge --check` — clean.
- `cargo check -p forge --all-targets` — no errors.
- `cargo test -p forge --lib` — 587 passed, 0 failed, 2 ignored (the WO-410 count, unchanged).
- `cargo clippy -p forge --all-targets` — none of the twenty-two converted sites drew a finding. The findings that
  remain in the two larger files sit in code this work order did not touch (`job/mod.rs`'s `heartbeat(&job_id,
  &worker_id)`, `opencode/mod.rs`'s `&live_turn` and its `drop` of a non-`Drop` value), and the rest are the
  pre-existing warnings of the in-flight edits listed below.
- The four binaries start with `init()` in place: `forge help`, `forge-task help`, `re-workflow help` and
  `forge-worker help` each exit 2 with only their pre-existing usage text on stderr, and `forge-worker` reaches its
  documented `DatabaseUnavailable` report (this shell has no `APP_ENV`) instead of a panic out of the subscriber.
- **The rendering was observed, not assumed.** A throwaway integration test — created, run, deleted; this repo keeps
  its integration tests in the `tests/` harness crate, and a permanent in-process subscriber would bypass libtest's
  capture and print raw log lines in every `cargo test -p forge --lib` run — installed the subscriber twice and emitted
  one `info!` and one `warn!` in the shape of sites 21 and 9. Under `RUST_LOG=info` it printed to stderr:

  ```
  INFO … spend story="WO-408" node="probe" run="1" tokens_in=12 cost_usd=0.500000
  WARN … forge-job: final ownership renewal failed; outcome preserved for reconciliation job="job-1" error=boom
  ```

  and under `RUST_LOG_FORMAT=json`, `{"timestamp":…,"level":"INFO","fields":{"message":"spend","story":"WO-408",…}}`.
  The double `init()` printed one line per event, which is the idempotence claim above, measured.
