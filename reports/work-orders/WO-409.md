# WO-409 Report

## Summary

The two functions in `db/src/forge_engine.rs` that clippy counted as having too many arguments — `open_hold` and
`record_observer`, each 8/7 — now take a parameter struct. Enforcement is at the compiler's level: the values are
named at every call site, so two `&str` ids that both cast to `uuid` in the statement can no longer be transposed
silently. The statements themselves and the order they bind are unchanged, so nothing about the schema interaction
moves.

## Pre-fix SHA

`2a330b0bc` (the WO-403 commit, the head this work started from).

## What "the listed functions" turned out to be

The work order points at a list in `reports/baseline.md`, and that file has never existed in this repository (the
same absence WO-402 and WO-403 recorded), so the list was derived from the gate the work order names. `cargo clippy
-p db --all-targets` at the base flagged eight functions; two of them are in the file this work order owns:

| function | args | file |
| --- | --- | --- |
| `open_hold` | 8/7 | `db/src/forge_engine.rs` |
| `record_observer` | 8/7 | `db/src/forge_engine.rs` |

The other six are in files no part of this work order owns: `db/src/forge_control.rs` (two, 9/7 — WO-405 and WO-410),
`db/src/app_error.rs`, `db/src/broker_signature.rs`, `db/src/signer.rs` (two). Those three files are owned by no
work order in this manifest at all; they are named here rather than left for a later reader to rediscover, and they
are the reason `cargo clippy -p db` is not silent after this commit.

## Changes Made

### 1. Two input structs, borrowed

`NewForgeHold<'a>` (the seven columns of a `forge_hold_record` row) and `NewObserverEvent<'a>` (the seven values the
recorder's trace statement binds). Both borrow, like `CompletionUnit<'a>` in the same file: nothing in them outlives
the statement that binds it, so no call site pays an allocation to name a field. `NewForgeHold` replaces the field
order of the old positional call — that order is why the DAO carries a test for a hold whose `task_id` never landed
(`tests/tests/forge_seam_hold_dev.rs`, the C1 regression).

### 2. `open_hold(&self, hold: &NewForgeHold<'_>)`

The statement text and the bind order are byte-for-byte what they were; only the sources of the seven values changed
from positional parameters to named fields. The `DbFailure` label (`forge_engine.open_hold`) is unchanged, and the
`$1::uuid` / `$2::uuid` casts the C1 fix added are untouched — this is the migration-compatibility evidence: the
change is a Rust signature, and no migration, statement or column is involved.

### 3. `record_observer(&self, event: &NewObserverEvent<'_>)`

Same treatment, same statement (`FlightRecorderDao::TRACE_EVENT_INSERT_SQL`, still one spelling, still reached
through the DAO), same ten binds in the same order, including the two the DAO supplies itself (`forge_observer` and
the absent timer job). `tests/tests/arch_boundary__005__...` asserts on the source text `pub async fn
record_observer` and on the caller containing `dao.record_observer(` — both strings still hold, and the suite that
carries them was rerun.

### 4. Call sites, and the export

Two callers of the DAO's `open_hold`: `forge/src/engine/hold.rs` (`open_forge_hold_record`, which converts its own
`OpenHold`) and `tests/tests/forge_seam_hold_dev.rs` (the DEV round-trip test). One caller of `record_observer`:
`forge/src/engine/observer.rs`. `db/src/lib.rs` adds the two names to the explicit `pub use forge_engine::{...}`
list. None of those four files is owned by another work order in this manifest; a signature change cannot leave its
call sites behind, so they are part of this commit and named here.

The forge-side port is untouched: `ForgeWriter::open_hold(&OpenHold)` and the implementations in
`writer.rs`/`db_writer.rs`/`smith.rs` still take `OpenHold`, and `db_writer.rs` still delegates to
`hold::open_forge_hold_record`. The struct the engine speaks is not the struct the statement binds, which is the
point of that seam.

  `too_many_arguments` hits are the six listed above, none in this work order's file.

- `cargo test -p db --lib` — 53 passed, 0 failed, 0 ignored.

- No positional DAO call remains: `grep` for `.open_hold(` / `.record_observer(` finds only the `OpenHold` port
  implementations and one source-text assertion inside the arch-boundary test.
